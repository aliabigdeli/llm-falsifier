Can a language model find the input that breaks a system?

A falsifier searches throttle and brake profiles for a run whose speed passes 120 inside that window. Such a run is a counterexample.

Robustness turns pass or fail into a signed margin

Robustness of the AT1 specification

Near miss: speed peaks at 119.6 inside the window, so ρ = +0.42 and the spec holds.

Counterexample: speed reaches 120.2 at t = 20 s, so ρ = −0.21.

Falsification is a search for inputs that push ρ below zero.

Classic falsifiers see only numbers. The names carry the physics.

scoreρ = 0.419
output and specspeed(t)G[0,20] (speed ≤ 120)

A numerical optimizer sees ten numbers and one score.

A language model can also read what each number means.

Throttle and brake drive speed, so hold the throttle high and the brake at zero.

Bayesian optimization, surrogate models, simulated annealing, automata learning and tree search all work from the first reading.

LLM-Falsifier puts a language model in the optimizer’s seat

The first input comes straight from the LLM, with no random warm-up. Each input costs one simulation, and the search stops at the first ρ below zero.

The critical time t* is the instant whose signal values set ρ. It is computed recursively over the formula, taking the innermost witness for nested operators.

Fewer simulations, not less time

Each iteration waits on an LLM call, and API use costs more than classic heuristics. It pays off when simulations are the expensive part.

throttle, brake → speedclear cause and effect
x1 … x10 → ylittle to reason about

It leans on meaningful names

Gains are largest when inputs and outputs carry physical meaning, and smaller where that link is indirect or missing.

Flat robustness stalls the search

In gear specs AT51 and AT54, discrete gears hold ρ on plateaus such as 0.5, leaving little signal to follow.

Not falsified within 100 simulations: AT51, AT54, NNβ and SC. The reasoning traces shown come from open-source gpt-oss-20b, not the GPT-5 models behind the main results.

Give the search meaning, and a language model becomes a sample‑efficient falsifier.

names + output trajectories + critical time → fewer simulations

Open directions: richer gray-box model information, and hybrids that hand fine-grained refinement to numerical optimizers.
